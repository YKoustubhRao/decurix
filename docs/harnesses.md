# Agent harnesses (TheBot, Claude, Ollama)

**New desktops all run TheBot; what they choose is its brain** (`Desktop.Brain`, `desktop-brain` label, `DECURIX_BRAIN` env; `httpapi.desktopBrain` refuses any other harness with 400, and a hosted brain nobody set up). `ollama` (default) is the shared local model as before. `claude` / `azure` / `openai` (any OpenAI-compatible server the control plane was given: OpenAI itself, OpenRouter, a Brainiac box on the own network; `llm.ProviderOpenAI`, 2026-11-01) point soul's OpenAI-compatible provider at the control plane (`LLM_PROVIDER=openai`, `OPENAI_BASE_URL=<control plane>/api/llm/<brain>`, a placeholder key) with `EMBED_PROVIDER=ollama` (embeddings stay local and best-effort), `DECURIX_LLM=<brain>` so `harness.ask_model` asks the same hosted model (and never falls back to loading the local one), and `thebot_harness.wait_for_backend` waits for soul only. The ollama/claude/azure harnesses below remain for desktops created before this, and `bench/gui/run.py --engine ollama|claude` no longer creates such desktops. The shared Claude Code login (`claudeauth`) is no longer offered in the dashboard.

**TheBot adapts to its brain (`agent/thebot/internal/llm/caps.go`, `llm.Capabilities` on `RunContext.Brain`).** New engine work goes into TheBot, keyed on what the model can do rather than on which provider it is:
- **Vision.** A hosted brain's is decided by the control plane when its key is saved (`llm.Hub.Test`: Claude's current models all read images; an Azure deployment is sent a one-pixel PNG and a refusal means text only), stored with the settings and baked into the desktop as `DECURIX_BRAIN_VISION`. The Ollama brain gets no such variable: soul asks Ollama `/api/show` (`capabilities` has `vision`, `model_info.*.context_length`) in the background until it answers - `/api/show` reads the manifest and never loads the model, which matters on this repo's memory-starved host. Never probe the shared Ollama with a chat.
- **What vision changes in the operator** (`skills/operator.go`). The contract gains `visionRule`. `gui` is run with `DECURIX_GUI_SCREENSHOT`, so every screen command leaves a PNG of the screen as it ended up (`cli.save_screenshot`, whole for a hosted brain, half size for a local one). The PNG is attached to that command's result, and only the newest screenshot is kept. `office read` is run with `DECURIX_OFFICE_IMAGES=attach`, so a scan's `[page image: ...]` pages are attached too. Up to `maxDocumentPictures` (6) pages are kept, *separately* from screenshots, so the screen never pushes the invoice out of view. A text-only brain gets `DECURIX_OFFICE_IMAGES=ocr` instead: tesseract's reading of each page, flagged as OCR. Dropping an old picture rewrites an earlier message, which costs a local vision model its Ollama prompt cache; that trade is accepted only for vision brains.
- **Budgets.** A hosted brain gets 16000 characters of command output (4000 local), 12000 of `gui` element list (`DECURIX_GUI_TEXT_CHARS`, 3500 local) and 40 operator turns (16 local). They are fixed on the goal's `operatorState` when it starts, so a paused goal resumes with the same ones.
- **Benchmarks run on a brain with `--brain azure|claude|ollama`** (`bench/brain.py`: the environment `buildDesktopEnv` gives a desktop with that brain; model calls go through this tree's control plane on 127.0.0.1:8080, which must have the brain set up; the skills bench's fake control plane forwards `/api/llm/*` there). Without the flag, `bench/recordings` and `bench/skills` start their desktop on the old model-free settings, as before. Verified on Azure (gpt-5.4, vision) on 2026-09-29: recordings, skills and learn_documents (including path A, where TheBot found the taught skill with `gui skill`, read the PO with `office read` and ran `gui do` with list values) all pass. For benches that `docker exec` into a desktop, run the control plane with `DECURIX_IDLE_STOP_MINUTES=0`: idle-pause pauses a desktop seconds after a task and `docker exec` refuses a paused container.
- **TheBot has the Office (GPT) engine's two back-office tools, as shell commands** (`tools/office.py`'s `main`, taught in the operator's contract):
  - `office update BOOK.xlsx -` takes a JSON spec on stdin: `edits` plus `replace_refs`. It edits the sheet XML in place, so charts survive; never rewrite a workbook with openpyxl.
  - `office create BOOK.xlsx -` makes a new workbook.
  - `office email --to --cc --subject --attach` takes the body on stdin and drafts into the Outbox through `tools/outbox.py`. The Office (GPT) harness's `draft_email` now calls the same module. A draft is never sent: only a person's Send on the Triggers page sends it. Its subject and body pass through the secret withholding first, and an attachment must be a file of the work (`~/work`, the shared folder, `~/Downloads`; never under a hidden folder or `~/.decurix`: `privacy.file_may_leave`).
  - TheBot's command safety does not stop `office email`; it stops only real senders (`sendmail`, `mutt`, ...).
  - Triage sends an email-to-prepare to the operator (`wantsEmailDraft`: draft/prepare/compose an email, reply, reminder, letter or message; the Outbox; or "write an email" with an address or an attachment). Left to the chat skill, it answered with the email's text and put nothing in the Outbox. "Help me write an email asking my boss for Friday off" names no address and stays conversation.
- `llm.Message.Images` carries PNGs, and each provider sends them in its own shape: OpenAI `image_url` parts (and so, through the control plane's proxy, Claude image blocks), Anthropic `image` blocks, Ollama `images`. `Message` is no longer comparable with `==`, so tests use `reflect.DeepEqual`.

Each desktop picked a harness at creation time (`Desktop.Harness`, `desktop-harness` container label, `AGENT_HARNESS` env var passed into the container — see `internal/httpapi/desktops.go`'s `createDesktopHandler` and `internal/desktop/docker.go`'s `buildDesktopEnv`). All three reach the exact same command/querytext/memory/progress contract through `harness.py`'s dispatch:

- **`ollama`**: the hand-rolled `COMMAND:`/`DONE:`/`HELP:` loop in `task_runner.py`, driving an Ollama model.
- **`claude`**: requires the developer or ai profile (`claude` binary isn't installed in basic) and a shared Claude Code login completed once through the dashboard's popup (see `internal/claudeauth` and `internal/desktop/claudelogin.go` above) rather than an `ANTHROPIC_API_KEY` in `.env` — `httpapi.createDesktopHandler` reads the stored session and `desktop.Manager.BeginProvisioning` seeds it into the new container's `~/.claude/.credentials.json` (`PersistClaudeCredentials`) only when the harness is `claude` and someone has logged in. Runs `claude -p "<task>" --output-format stream-json --verbose --permission-mode bypassPermissions --settings <guard hook> --disallowedTools "Bash(xdotool:*),..." --append-system-prompt "<memory + safety rules>"`, optionally `--resume <session_id>` to continue after a human responds. No `--bare`: that flag forces API-key-only auth ("OAuth and keychain are never read" — confirmed against the CLI's own `--help`), which is exactly what this harness now needs to *not* do; the trade-off is that `--bare`'s other isolation (hooks, LSP, plugin sync, attribution, auto-memory, CLAUDE.md auto-discovery) is back on too, same as running `claude` anywhere else — none of it matters inside a desktop's empty `~/work`. Every tool stays allowed without a prompt (a headless run has nobody to answer one), but behind a PreToolUse hook the agent ships, `claude_guard.py` (`claude_harness.PERMISSION_FLAGS`, review 2026-11-02): it refuses (exit 2, the reason shown to the model) a Bash command that sends input or drives windows (xdotool, xte, ydotool, wmctrl), reaches the browser's DevTools port or this desktop's own agent ports (9222, 8080, 8081, 4900, 8092), or touches the gate's state and the person's reply channel (`~/.decurix/command`, `~/.decurix/computer`, `approval.json`, `*-reply.txt`, the task file, the agent token); the same for a Write/Edit to those files and a WebFetch of those ports - and tells the model to use the computer tools. Deny rules for the plainest programs hold in every permission mode as well. It fails closed: a call it cannot read is refused. **This is a guard rail, not a boundary:** the shell runs as the same Linux user as the gate, so `x"do"tool`, a script written to a file and run, or a raw socket gets past the words; the boundary is a separate Linux user for the gate and its state, which is not built yet. Not verified live against a Claude Code build (unit tests only); the hook's running under `bypassPermissions` is from the docs' description of the hook input (`permission_mode`), not a live check. `stream-json` (which *requires* `--verbose`) is what lets the turn be watched as it happens; its final `result` event carries the same fields the one-shot `json` format returned, so only `_run_claude` knows the difference.
- **`thebot`** (default: the create dialog lists TheBot, Claude, Ollama in that order, and the API picks it when no harness is given): TheBot's `soul` binary, built from `agent/thebot/` (its own Go module) into all three images and started as a daemon on port 4900 when `AGENT_HARNESS=thebot`. Reuses the same `OLLAMA_URL`/`OLLAMA_MODEL` every desktop already gets, so it needs no env var of its own. Inside soul a job goes: **recall** (L1 facts) → one shared **system frame** (`internal/prompt`: persona + host context, byte-identical for every model call in the job so Ollama's prompt cache carries across them) → **triage** (`internal/atomizer/triage.go`, deterministic: `chat` / one `skill` / `operate` / `plan`) → a tagged step **graph** from the planner only for `plan` (`[do] [shell] [web] [read] [download] [write] [code] [docs] [answer]`, with `(after N)` dependencies) → the **scheduler** (`internal/scheduler`) runs ready steps in parallel under a process-wide model-concurrency limit (`llm.Limited`), recovers a failed step (retry / decompose / ask), replans the rest once if it still fails, and **pauses** with a `Checkpoint` when a step needs approval or an answer → one **synthesised reply** for multi-step jobs. `operate` is the **operator** skill (`internal/skills/operator.go`): a Go `COMMAND:`/`DONE:`/`HELP:` loop carrying the Ollama harness's measured lessons, which is what lets TheBot answer "what's the kernel version?" by running `uname -r` instead of planning a web search. Consequential commands and requests are stopped by `internal/safety` before they run, whatever the model decided.
  - **What soul reports as done (2026-11-02): fail closed.** A step's `Verified` is a success the step saw, nothing less. The browser skill verifies only a run the extension finished with an answer; an error, captcha, stall, timeout or answerless "done" is a failure marked `fatal` (not retried), with the log of what it saw. The terminal skill never verifies a nonzero exit (an empty stderr included; marked `fatal` so recovery does not swap in an unrelated command that exits 0), with one exception decided by the program the command line ran last (the first word of its last stage, `negativeAnswer`), never by output text: exit 1 from `grep`/`egrep`/`fgrep`/`zgrep`/`rg` ("no match"), `diff`/`cmp` ("the inputs differ") or `test`/`[`/`[[` ("the test is false") is that program's answer, reported as `answered` (`Meta["answered"]`, "Exit code: 1 - answered: no match"), not as the work succeeding and not as fatal. `grep x f && echo found` still fails. A command that exited 0 while a backgrounded child still held its pipes (`exec.ErrWaitDelay`) is a success everywhere a shell runs (`hostshell.Exited`: the terminal skill, the operator's shell, the coding harness). The coding skill verifies only `BuildReport.Succeeded()`: tests pass, the project builds, and a smoke start (when one ran) started. file-write keeps a Markdown/text file's fenced blocks whole (only a reply that is one fenced block is unwrapped; several blocks for one code file are not guessed at), takes no version number for a file name ("Go 1.27"), and verifies by reading the file back. download (and every page fetch: `internal/websearch`, the coding harness's research) goes through `internal/netguard`: it resolves each host and dials only public addresses - not loopback (soul 4900, the agent API, Chrome 9222), RFC 1918 (host.docker.internal, decurix:8080), link-local (169.254.169.254), unique-local, CGNAT 100.64/10, unspecified or reserved - checked on the address actually dialled (no DNS rebinding), on every redirect, with no proxy. A URL is taken only from the request, the person's reply, or a page a verified step fetched (`givenURL`, `PriorSourceURLs`), never from a model's prose. download checks each file's bytes against its kind (a login page under `invoice.pdf` is not saved), verifies only when every file found was saved, and bounds every read (`maxPageBytes`, `maxFileBytes`). A chat reply, a web skill's summary and a RAG answer are marked `MetaModelReply`: later steps see them labelled as a model's own words (`PriorFindings`), and the operator never notes them as seen (`PriorSourcedFindings`), so a web page's text cannot become a traced source for what the shell loop types. In the operator, a stalled loop (a command repeated past its nudge, unmarked replies, a bare DONE) puts what it has to the person as "Not checked", never as a verified result. The commit gate's verifier and case matrix answer an error, a 429, an unreadable or cut-off answer with a "Not checked" point (`notChecked`, never advisory), not a pass. The providers mark a cut-off answer (`llm.Result.Truncated`: OpenAI `finish_reason` length, Anthropic `stop_reason` max_tokens, an Ollama stream that ends without `done` - which is also an error, retried); the operator asks again for a cut-off reply instead of acting on it, and the chat, web, file-write, reviewer and verifier calls never take one as complete. `canonicalNumber` strips only a currency's mark, so "INV 5000" is an identifier, not 5000. `saysWhyLeftOut` needs a stated reason (because, a duplicate, another client's, another period's), not a bare "no"/"not". `safety.IsApproval` is false for a reply with a question or a condition in it ("ok, what will this send?", "yes if the total matches").
  - **A fix a web page or a model proposed is a proposal (2026-11-02).** In the coding harness (`coding/diagnose.go`) a `FIX_COMMAND` from web research or a model's reply (`Diagnosis.IsProposal`; the built-in table's fixes are not) runs only with the person's yes to that exact command: the build stops (`BuildReport.NeedsApproval`), the coding skill pauses with `NeedsApproval` and a `codingCheckpoint`, and on the re-run the same failure gets the command they saw, once (the scheduler's single-use grant); a no declines it for that run. A researched fix is written to L1 only after it ran with approval and the check that had failed then passed (`settleLearning`).
  - **What L1 keeps.** `memory.L1.Store` refuses a secret-shaped fact (`memory.LooksSecret`: a password, PIN, OTP or code given after its name, a token or key by its shape, credentials in a link, a long mixed random string), whoever asks; `feedback.RecordNegative` does the same. A judged fact (`ConsiderExchange`) is stored only if every value-shaped token in it (a number, an identifier, an email) is in what the person said: a value the answer carried from a client's documents has no scope in L1 and would be recalled into every later task.
  - **A yes is one action's, once.** The scheduler hands the person's yes to the paused step only, as a single-use grant (`singleUse`): used up by the first `IsApproved` of that exact action, withdrawn when that run ends (`runStep` clears `rc.Approved` before any retry, reroute or decomposed recovery), never written into a `Checkpoint`. A retry after a failure, a second identical command, or a resumed job asks again. No request approves itself: soul's `/api/chat` has no `approved` field and `scheduler.Request` no `Approved`, so the check on a consequential request's own words is asked every time (the Python harness's `"approved"` is ignored).
  - **Who may call soul (`cmd/soul/guard.go`).** Soul listens on every interface of the desktop container, so other containers on the Docker network reach port 4900 too. Before any route: a write that is not `Content-Type: application/json` is refused (415: a page in the worker's Chrome can POST text/plain with no preflight), and so is a request whose `Origin` is not the Host it was sent to, or whose `Sec-Fetch-Site` is another site (403). Every `/api/` route but `/api/health` needs `Authorization: Bearer <DECURIX_AGENT_TOKEN>` (`config.AgentToken`), compared in constant time (401). Without a token soul fails closed: those routes are refused (401, "created without an agent token: recreate it") until the desktop is recreated with one; it no longer serves an open API. The control plane's `/agent/<id>/` proxy sends that header (`desktop.AuthorizeAgentRequest`), as does `thebot_harness` (`config.agent_auth_headers`). The SOUL_HOST default stays `0.0.0.0`.
  - **Commands in their own process group.** `hostshell.CommandContext` starts the shell as a group leader and, when its context ends, kills the whole group (`cmd.Cancel` → `KillTree`, `WaitDelay` 2 s): killing only bash left a build's compiler holding the pipes, and the terminal skill and the coding harness's builds hung past every timeout. `hostshell_windows.go` exists only so the module compiles and its tests run on a Windows development host (bash from Git).
- All three system prompts (`SYSTEM_PROMPT` in `ollama_client.py`, `SAFETY_SYSTEM_PROMPT` in `claude_harness.py`, `SAFETY_PREAMBLE` in `thebot_harness.py`) instruct the agent to stop and request human approval — via the same `HELP`/`ask_for_query` → querytext path — before payments, sending messages on the human's behalf (WhatsApp/email/SMS), or any action with real-world consequences it isn't fully confident about. Claude and TheBot signal it with a `NEEDS_APPROVAL:` prefix on their final answer; the Ollama loop uses its `HELP:` control signal.

**Which app a request asks to work in (`atomizer.WorkApps`, 2026-10-19).** Triage and the operator's `behindTheApp` share one reading: "use/using/with APP", "open it in APP", "in APP (the app on your desktop)" name where to work; "in/into/on APP" followed by a file of that app's kind (", orders.xlsx", "(orders.xlsx)") or by "format/file" names the file's format, and the file is made with `office`. The operator is also told once, when under 40% of its goal's time is left (`timeNoteFor`), how its screen actions went and to finish, save and check (or ask) before the job limit; a `gui type` with shell-doubled quotes is sent back to use stdin (`quotesNudge`), and the grounding check reads a heredoc's body and traces a formula's quoted words like typed text (`formulaLiterals`).

**Long goals and what a result rests on (2026-10-22, hosted brains only).** A goal's context is managed in `skills/context.go`: once the re-sent transcript passes `contextBudgetChars`, or a turn budget is spent by a window that made progress (up to `maxContinuations` more budgets), the older part is replaced by one progress message (the model's own NOTES, the harness's `Ledger` of what every command did, every word the person said in the goal) between the untouched prefix and the newest messages; the "few turns left, finish" note comes only when no budget follows. What a compaction keeps is bounded in characters (`keepRecentChars`, `ledgerShownChars`), and another is not tried until the transcript has regrown (`compactRegrowth`). A ledger line whose output it shortens names a file holding the whole output (`keepOutput`), so a step can be read again even when its screen has since changed. Between compactions a hosted goal's transcript is only appended to: stale screen listings, screenshots older than the newest and older command outputs (masked to their start and a file holding the whole: `maskOldOutputs`) wait for one maintenance pass (`maintain`, when `maintenanceDue`), because on GPT-6-class deployments any rewrite of the transcript's tail threw the prompt cache away - measured 2026-11-01 on three office workflows, the cached share went from 27-35% to 54-70%, same checks, about 40-60% less input billed at the full rate. Every call carries a `prompt_cache_key` per goal and call kind (`llm.cacheKey`), dropped for good if a provider refuses it. A local model keeps the per-turn digests. `skills/judgements.go` asks, before a DONE and before an action the approval gate stopped (each kind with its own cap of rounds), for the JUDGEMENTS the result rests on, each with its backing quoted; code only finds where each quote stands (whole words, or only its words near each other) in what the goal was shown, and the approval shows the list ("What this rests on"). `skills/reviewer.go` is the one place judgement is made about the result: an independent model call (tried twice) is shown facts that code gathers with no verdict of its own (the request; every reply of the person with what it answered, kept apart from the transcript so compaction never loses it; the worker's memory and lessons; every command with what it printed; documents saved and offered on screen; web pages looked up; the passage around each cited quote; points an earlier review raised; the report and its calls) and names what is not done, not taken in, not established or contradicted, each with how it is settled (recheck, lookup, person). Per round that goes back once to the operator; what is still open goes to the person as one question, numbered through and told as what each point is (up to `maxReviewQuestions` a goal); past that it is carried with the report or the approval ("Still open after an independent review"), never dropped - and a review that could not be made says so. The question asked is given back with the answer. A gate stopping a command while points are being settled carries them to the approval. The harness does not add pattern- or threshold-based nudges for judgement; code blocks only on what it decides for certain (a broken file, a secret, the approval gate). A web page is a source only once the person vouches for it; a link the person gives is a source at once. `office update` takes `insert_rows` (references move with the rows) and `copy_rows` (the next period's block made from the last one as a copy and paste: references move, the period's name is replaced in labels, typed figures and labels carrying a date or a reference are left to fill, nothing is written over a filled cell, formulas reading another sheet are named to check), and `office read` maps a sheet that repeats one layout and tags each row with its block (`sheet_blocks`) - a long one shows its newest blocks whole.

The operator's guards read a command line as the shell runs it (`shellSegments`): each gui command of a chain on its own, a here-document as its command's stdin. `quotesNudge` sends back any gui type whose quoting the shell would change (a quote opening or closing mid-word, a formula with odd quotes or unmatched brackets); the contract says every formula goes on stdin (`gui type CELL - <<'EOF'`).

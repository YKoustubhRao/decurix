# Skills that heal, escalate and learn

Exact replay halts the moment a control is not where it was recorded. A skill run (`/skill`, skill_task) now has a ladder in front of that halt, and a memory behind it - Orby's planner/grounder split and "observe, learn, automate" loop on the parts above. Opt-in per `replay.run(..., ladder=)`: `/replay` and a bare `replay.run` still halt exactly as before, so a recording replays *as recorded* and only a taught skill adapts.

```
step's target not found as recorded
  1. heal    healing.rank/decide  score each candidate on name, container, neighbours, position, role;
                                  take one only if it clears ACCEPT *and* leads the runner-up by MARGIN
  2. ground  escalation.Ladder    ask this desktop's own engine (harness.ask_model) to choose among
                                  the numbered candidates, or say 0
  3. ask     skill_task           the candidates numbered, what was tried, "reply 1"; one word answers it
```

The same ladder has two narrower jobs:

- **Detours** (`Ladder.detour`, `detour.py`). When a target is missing and the screen now looks like the recording's screen at a later step, the steps in between dealt with something this run does not meet (a pop-up, a CAPTCHA). They are left out and the run says so. The engine, reading the screens' text, may agree or overrule (`DETOUR_CONFIDENCE` 0.7); without it only a clear lead (`detour.SURE_MARGIN`) is taken.
- **Position-only clicks** (`Ladder.ground_point`). A click recorded only as a point whose picture is not on the screen is placed by reading the text the recording clicked (OCR) and finding the line that plays that part now; failing that, a grounding model looks for what the person said the step does (`grounder.locate`), and the point is taken only when it lands on a control. Never for a strict step.

- **A guess never passes for a match.** Confident needs the score, the label similarity and the lead to each clear a bar, and the name must be one the step is known by (`healing.keeps_identity`, below). Likeness and synonyms rank the candidates; they never heal onto another name. A containing label scores 0.75 on purpose ("Delete" vs "Delete all" are different actions), so a name alone never suffices; position, container and neighbours have to agree. Letter-overlap only counts for near-typos (ratio >= 0.8) - `save` vs `archive` reaches 0.6 otherwise, found by a test that "healed" it.
- **A step that could do harm is strict** (`healing.strict`: approval-gated, or optional): it heals only onto its own control - the same role and a name it is known by (recorded or a proven alternate), word for word, moved or redrawn - and it **never reaches the engine**. No step heals by likeness onto a control the gate stops, or one whose label commits to something the recorded one did not (`healing.retargets`: "Save" -> "Submit", "Save and Submit", "Update"); the engine's pick is held to the same rule, and such a candidate goes to the person. Saving and submitting are not synonyms (review 2026-11-02: Save~Submit scored 0.90 against ACCEPT 0.72). The approval gate in `core.act` is not on the ladder and nothing here can grant one; a yes is still one action's. `_approval_text` only tells the person more (what the step does, what it would type, what it led to when recorded, whether the control was found by a repair).
- **The engine is a grounder, not an agent.** `harness.ask_model(system, prompt, purpose=...)` is one question, no history, no tools. When the control plane has a hosted model, it answers for every engine (`llm_client.ask_once`); a desktop whose brain is the hosted model never falls back to a local model. Otherwise it is the engine's own (`claude -p --tools ""`, or Ollama `/api/chat`; TheBot has no single-question endpoint so it asks the Ollama it already uses). `harness.py` is still the only file that branches on the engine. It picks from the list the screen actually has; a choice outside it, prose instead of JSON, confidence under 0.75, a timeout or no engine at all is "not sure" and drops to the person. `DECURIX_ESCALATION_MODEL_CALLS` (default 3 per run, 0 disables) bounds it - on a CPU host an abandoned request keeps evaluating (see the Ollama gotcha), so a run must not fire an unbounded chain. It is only offered while `state.backend_ready`. The two system prompts are constants so Ollama's prefix cache carries.
- **A result that is not there exactly can be *judged*.** `Ladder.judge` asks the engine whether the screen shows the step did its job (needs 0.85). That is a judgement, not a check: such a step counts as unverified, so the run ends `completed_unverified` and says "took the screen's word for step N" - `replay.py` still never reports a success it did not see. Never for a `consequential` step, whose missing result stays `reconciliation_required`.
- **Learning (`experience.commit`) keeps a lesson only if the run then succeeded** - the rule `_retarget` already had, made general. A repair the screen confirmed (the step's expected result appeared) becomes an `alternates` entry at once; one nothing confirmed must repeat `PROMOTE_AFTER` (2) times; a control a person picked is kept by `_retarget`, which now files the old name as an alternate too. `locate` (box + neighbours) is refreshed only from a step found as recorded or a repair the screen confirmed. A run that stopped or failed records history *on a fresh copy read from disk* (`skill_task._settle`) - the run's own copy holds corrections not yet shown to work.
- **A skill reports its own wear.** `experience.health`: a step that needed a repair or a person in 3 of its last 5 runs is *fragile*; `_finish` appends "record it again and `/learn` it", and `skills.summary` carries `health`.
- **Ingestion keeps what healing needs.** `compile_program` adds `step["locate"]` (the recorded box and screen size, beside the target so nothing comparing targets changes) and `phase`/`phase_label` (a change of window starts a phase), which a question shows as "Part 2 of 3: Customers". The container names come from the target's own path.
- **An engine running `gui do` gets healing only** (`skill_engine.run`: a ladder with no model and no person) and keeps nothing: a skill is rewritten by a person's correction or by a `skill_task` run, never by an engine's.
- **Not built, on purpose: a standing approval** ("always allow this"). It would be the skill switching off the gate, which the section above forbids; the richer approval text is the safe half of it. **Not verified live:** the engine calls (`ask_once` for Claude in particular) and the ladder against a real desktop - the unit tests script the engine and the screen, `bench/skills/e2e.py` has not been extended to a renamed control. Do that before relying on the model rungs.

The benchmark is `bench/gui/`: 20 tasks (12 in a web admin panel, 5 in LibreOffice, 3 in GTK apps, 3 of them approval checks), fixtures and outcome checks that run inside a desktop (`fixtures/bench.py`), and `run.py`, which drives each engine through the control plane's chat API on a fresh desktop and reports success rate per engine. `--engine oracle --container <desktop>` runs each task's scripted `gui` solution with no model — the proof that a task is solvable and its check is right. Results go to `bench/gui/results/` (gitignored).
## Since the review of 2026-11-03

- **Healing never changes the name.** A repair may find a control in another role, container or place, never under another name (`healing.keeps_identity`). A renamed control is asked about once, and any healed or grounded step makes the run `completed_unverified` ([recordings.md](recordings.md)).
- **TheBot's review points no longer read business words.** The code-decided review points that did are gone or turned into facts for the reviewer: cancelled records, `notDoneRe` routing, rate lines (`rateLineFacts`), month folders (`folderNameFacts`, with no blocked mkdir), revision words in messages, and "not done" words for handoffs. Whose a point is now comes from the reviewer's `settle` value. An unopened message counts by a declared record in its subject: its own tokens in order, or its running number (the key's last token, with a digit and at least 3 characters); a year never counts on its own.
- **The GST bench** must be run again, because the review points changed (see [follow-ups.md](follow-ups.md)).

# Gotchas, part 5

- **A line of text goes into a Windows app's field as its value, not as keys** (`bridge.ps1` `SetValueAt`, `winhost.Session.SetValue`, the viewer's `setvalue` input and `window.decurixSetValue`, `cdp.set_in_app`, `core.RELAYED_SETTABLE`/`NOT_SET`, backend `relayed:set`). Typed key by key, text raced the app: a key overtook the last characters ("D20" into Excel's Name Box went to D2) and spaces were dropped or doubled. A single line (no tab or line break) typed into a host-app viewer's textbox/combobox/searchbox/spinbutton is set through UI Automation's ValuePattern on an Edit or editable ComboBox of one line (never a Document or a field taller than 60 px, never a password field), the field is given the keyboard, and the value is read back (retried for ~1 s). Errors from before anything was set carry `NOSET` and only then is the text typed instead; any other failure is an error that says the text may already be in the field - found live: the first version reported every success as a failure (the Go session stripped the "SET " the viewer looked for) and the fallback typed it again, "D20D20". Verified on real Excel: D20, A20 and C17 by the Name Box, each `relayed:set`, the cursor on C17.
- **The final check reads what a task saved on the person's computer** (`GET /api/host-files/read`, `httpapi.hostFileAsked`/`hostFileReadHandler`; `produced.saved_on_host`/`copy_from_host`/`_host_findings`). Agreed by the person on 2026-10-16. Same rule as the stat: primary listener only, a C: path written in that desktop's own running or waiting task's request, no `..`, at most 30 MB. A requested host file that is there as asked (right name, kind and time) is copied into `~/.decurix/computer/host-copies/` and read by the judge with the task's other produced files - correct-looking workbooks with a header that was not bold, or a total over damaged data, had been reported done.
- **Reliability is measured by repeat runs** (`decurix-tests\wide\gui\guirun.py --repeat N`, `report.py [--last N] [--since DATE]`): per task the runs, right, rate, whether the last N were all right, the median time of a right run, and - apart - how many runs reported done when wrong (must be 0). Baseline on 2026-10-16: 102 runs, 23 right, 8 reported done but wrong (Excel 4, Word 2, Tally 2).
- **Not built: a host app's own documented interface** (TallyPrime's XML-over-HTTP on port 9000). Designed as a guide declaring the interface, the control plane matching it to an app kept on that desktop and checking the caller's container address, and the Windows bridge posting to the host's loopback; the bridge half was refused by the session's safety classifier (a new path from a VM to a port on the host) and was not built. Needs the person's explicit decision and permission.
- **A skill run's targets follow this run's values, and a detour never skips the choice** (`replay.follow_values`, `_detour_refused`, `_typing_checks`; `healing.rank`'s `avoid`; `core._what_it_acts_on`; `learning._name_points`, `rename_params`; `skill_task._settle_from_study`, `_first_attempt_text`). Found live (2026-10-16, worker gama, a WhatsApp skill taught from one demonstration): asked to message "Happy Family", the replay typed the search, the detour judged the screen to look like the recording's step 6 (the previous chat, Koustubh OG, was still open behind the results) and left out the click on the result; step 6's field, recorded as "Type a message to Koustubh OG", matched that chat exactly; the approval said only "click Send" and the message went to the wrong person. Now: (1) a target whose name holds what the demonstration typed, in a run that types something else, becomes this run's value matched by words (`contains`), path dropped, and a control named for the demonstration's value is never taken (`avoid`, also kept out of healing's candidates); a result clicked right after typing whose name is only a date or time (a chat row read as "10/9/2026") is found by the typed value; (2) a detour may not leave out the click right after a typed value, and its landing step's control must be on the screen now; (3) a `type` step is checked by its field, not by whatever else appeared (a hover's "Context menu for message from ..." halted every run); (4) an approval request names the filled fields beside the action ("textbox "Type a message to Koustubh OG" holds "hello hello, test""); (5) a run the check sent back says first what its first attempt got wrong and that what it sent stands. Lessons: a press the recorder kept as a point is named by the next step's control when that control's box holds the point (the click before typing a message), and a desktop press that opens a window one launcher makes is that launcher (`step["launcher"]`) - neither is asked about; the study names the task and each value by what it is (`name`, `names`: `{contact}`, `{message}`, not `{type_a_message_to_koustubh_og}`), a value in the person's own request is not asked about (it changes), the positional question describes each press by what the study saw there and accepts a control's name, and a bare `stop` to a question that offers stopping is an answer, not the end of the lesson. Verified on gama's live screen (read-only): with Happy family open, step 4 resolves to its row and step 6 to its own message box. Not re-run end to end: a lesson and a send after the change.
- **A dialog's combo box is typed into, not set** (2026-10-17, `bridge.ps1` `SetValueAt`, `TestSetValueLeavesADialogsComboBoxToTypedKeys`). Found by reading the traces of a repeat-run batch: `word_host` failed 7 of 7 and `ppt_host` 4 of 6 with the file "not in the folder the request named". The worker typed the full path into Save As's "File name:" and pressed Save; the box showed the path and read it back, and Word saved `Doc1.docx` in Documents under its default name (the file's time was the Save click's, to the second). `SetValueAt` set the box's inner Edit through UI Automation's ValuePattern; setting the combo that holds it did the same. The dialog takes the combo's text from the keyboard path only (Excel's dialog happened to accept the set value, which hid it). A field that is, or sits in, a ComboBox inside a dialog (`#32770`, or any owned window) now answers `ERR NOSET`, so the caller types the text with keys. Checked live on real Word: the same typed path then saved into `Decurix demo`; `word_host` went from 0 of 4 to 3 of 3. Not covered: a combo box outside a dialog (Excel's Name Box) still takes a set value, on purpose.
- **Typing that changes nothing was not typed** (`core._nothing_typed`, `NOTHING_TYPED_NOTE`). After PowerPoint's Insert Table the table is selected, not being edited, and text typed with no target goes nowhere; the result said only "nothing visible changed - check whether the action reached its target", and a run ended with the table empty after four such typings. A typing aimed at no field, of 3 or more characters, whose result changed nothing now says that nothing was typed and to click into the cell first. Reproduced live: after a click in the first cell, `Region`, Tab, `Revenue`, Tab, `North`, Tab, `812` all landed. The PowerPoint guide said the cells are listed by ref after inserting; they are not.
- **A repeat run needs a restarted worker** (`decurix-tests/wide/gui/guirun.py`, `GUIRUN_FRESH=1`, `tally_reset`, `erp_cleanup`). Run back to back on one worker, tasks failed on the last run's leftovers: windows from other apps took the keys, a document of the same name was still open ("Object already exists"), GIMP kept its export state, a Tally company from the run before blocked the next ("Another company with same name is open"), and ERPNext already held the supplier. With a restarted worker for every run, `writer_letter`, `impress_deck` and `calc_sales` went from 3/9 to 6/6. Read a repeat-run rate only from runs that start clean.
- **Where a "wrong" run is not a wrong report.** In 24 runs of 8 app tasks (2026-10-17) every run that failed ended by asking the person or saying it could not finish; none reported done when it was not. The host-file check (`produced.missing_on_host`) and the final gate are what held that line.
- **A workbook a script wrote has no formula results** (`office.formulas_without_results`, `produced.store_results`, `skill_task._gate`, `office calculate`). openpyxl writes a formula with an empty `<v>`; Excel and LibreOffice work it out on open, but pandas, an import, a preview or openpyxl `data_only` see blanks. Found live (2026-10-19, xl_lookup_any): the operator wrote the lookup workbook with an openpyxl script, read it back with `office read` (which calculates on a copy) and reported "completed and verified"; every price in the file handed in was empty. Now the final gate stores LibreOffice's results in every workbook the task wrote before judging it (formulas kept; an empty-text result is stored `t="str"` with an empty value, as Excel and LibreOffice write it, so it is not mistaken for a missing one), and a workbook that still has none is `not_done` with no model. `office read` says "Formulas without stored results" from the file's XML, not from openpyxl's None (which an empty-text result also reads as).
- **An app named next to the file asked for is its format** (`atomizer.WorkApps`). "Make his order sheet in Excel, wa_orders.xlsx in my work folder" was read as "work in the app": `behindTheApp` sent the operator's openpyxl script back, and it typed the sheet into Calc cell by cell until the 25-minute limit, with nothing saved (2026-10-19, wa_orders). "in/into/on APP" followed by a file of that app's kind (", x.xlsx", "(x.xlsx)") or by "format/file" is the format; "use/using/with APP", "open it in APP.", "in APP (the app on your desktop)" still name where to work.
- **Rows of a spreadsheet go in with one command** (`core._type_sheet_block`, `_read_back_block`). Each `gui` action costs about 10-20 s on a busy desktop (two full looks - the AT-SPI walk plus up to 60x26 sheet cells read one D-Bus call at a time, each capped at 6 s - a settle wait, screenshots, the audit and chat step), and a Tab in typed text was refused (rightly, for forms). Five rows took 76 actions and ran out of time; four GST headers took 8 actions with Accept-button clicks. Text with Tabs/new lines aimed at a sheet cell (or typed with no target while the active sheet has the focused cell) is now entered row by row via the Name Box and read back cell by cell; a cell AutoInput completed, a number read as a date or a formula showing `#NAME?`/`Err:` fails the command with exit 4. Form fields keep the one-field rule. Not done for a host app (Excel in a viewer).
- **The shell eats a formula's doubled quotes** (`gui type REF -`, `skills.quotesNudge`). `gui type "=IF(D2=""maharashtra"",1,0)"` is bash concatenation: the sheet got `=IF(D2=maharashtra,1,0)` and showed `#NAME?` (2026-10-19, calc_gst). `gui type [REF] -` takes the text verbatim from stdin (a heredoc); soul sends a `gui type` with `""` between characters back with that form, and its grounding check reads the heredoc body, so stdin is no way round it.
- **A formula built from the request's words is not a guess** (`skills.formulaLiterals`). Any quoted text made a whole formula "a value never read": `=IF(TRIM(D2)="maharashtra",E2*9%,0)` was refused twice and the operator was pushed onto typing computed figures (2026-10-19). Quoted text is now traced like typed text (in the request or what was read), numbers as before, and 0 and 1 are a formula's own structure.
- **Keys never land in a window an earlier task left** (`core._task_windows`, `_left_from_before`, `_adopt_front`). A task that timed out left its spreadsheet open; the next task's `gui type "=11,160"` with no target replaced A1 of that sheet (2026-10-19). The windows open at a task's first look are recorded; keys with no target from the engine's `gui type`/`gui key` are refused while the window in front is one of them that the task has not worked in (acted on by ref or point, `gui open`, `gui front`). Replays and a person's actions are not asked. Open documents are not closed between tasks: they may be the person's.
- **A task is told when most of its time is gone** (`skills.timeNoteFor`). Nothing in the operator loop said the 25-minute job limit was approaching; wa_orders spent all of it on one value per action. Once, when under 40% of the goal's time is left, the operator is told how many screen actions it ran and their average cost, to put rows in with one command, and to save, check and report or ask before the limit.
- **A gui command chain is checked command by command** (`skills.shellSegments`, `typedValues`, `segmentValues`). `typedValues` took the last word of a whole `gui type e1 "D1" && gui key enter && ... && gui key ctrl+d` chain as the text typed, and refused "ctrl+d" (and later "ctrl+enter") as a value nobody had given (2026-10-19, real Excel). Commands are now split as the shell runs them (;, &&, ||, |, line ends; separators inside quotes are text; a here-document is the stdin of its command), each gui type/select/do is read on its own, and a key chord is never a value. One command typing into a search box no longer excuses the rest of its chain.
- **Any quote inside a gui type's text is caught** (`skills.quotesNudge`, `mixedQuoting`, `unbalancedFormula`). Besides `""` doubling, `gui type "=IF(D2="NOT FOUND","",C2*D2)"` closes and reopens the shell's quoting: real Excel got `=IF(D2=NOT FOUND,,C2*D2)` and showed FALSE (2026-10-19). A gui type with a word whose quoting opens or closes mid-word, or a formula with an odd number of quotes or unmatched brackets, is sent back to give its text on stdin; the contract now says every formula goes on stdin.
- **Rows into a host app's sheet are typed as a person types them** (`core._type_relayed_block`, `_read_back_relayed`, `_relayed_cells`). In real Excel through the viewer two columns of formulas took 68 actions over 26 minutes (each through the Name Box, whose set value timed out once - bridge `SetValueAt`'s 6 s wait, `HELD?`) and nothing was saved. A block typed with no target in a host-app viewer that lists sheet cells goes where the app's cursor is: each cell's text, Tab, Enter after a row (Enter after a run of Tabs returns to the run's first column), with short pauses so a key does not overtake text. It is read back from the viewer's `row "D2 = 640"` list, anchored where the changed cells begin; a cell that differs, an error, or no change at all exits 4. The host clipboard is not used: `winhost.Session.Paste` keeps it the person's on purpose, and `/api/host-bridge/clip` runs xclip where the control plane runs (a container in WSL here), not in the Windows session. Not verified on live Excel.
- **Text typed into a host app's cell being edited is not lost** (`core._nothing_typed`). In a host-app viewer the cell being edited shows its text only once it is entered, so a formula that had gone into the cell was reported "NOTHING WAS TYPED" and typed again (2026-10-19). The note is no longer given on a relayed viewer's page.
- **Keys with no window in front go to the desktop** (`core._nothing_in_front`). Closing a previous task's leftover windows, the worker pressed Alt+F4 with nothing in front and XFCE offered to log out (2026-10-19). The engine's `gui key`/`gui type` with no target is refused while no window is active.
- **A Total row is formulas, not typed numbers** (`office.typed_totals`, `produced.typed_totals`, `skill_task._gate`, operator contract). A GST register asked for "with formulas" had its Total row typed in (2603800, 99342, ...): right that day, stale the day a row changes (2026-10-19, calc_gst). A row labelled Total/Sub-total/Grand Total whose cells are typed numbers equal to the sum of the column above them is `not_done` with no model asked when the request asked for formulas (`produced.formulas_asked`: formula(s), live, so it updates); otherwise a correct typed total is a correct answer and the report only notes it (PM decision: sending every workbook back over it was cost and noise without a gain in correctness). The contract says a total of cells is a formula over them.
- **The saved file decides a file deliverable, not the screen** (`verify.judge(deliverables=...)`, `produced.asked_files`, operator contract). A correct, cleanly saved register was refused because the screen still showed a range the worker had filled by mistake and cleared, and the action log showed the mistake; the person was asked (2026-10-19, calc_gst). When the request names files and they were saved, the check is told that the saved files decide that part: a corrected misstep or an unsaved change on the screen goes in its note. Strict facts about the file (results stored, typed totals, where it was saved) are still decided in code. The contract says a document the worker saved holds no change it made after saving (undo it, or save it if it belongs).
- **A block aimed at a cell by its coordinate takes the block path** (`gui type D1 ...`, `cli.CELL_TARGET`, `core._sheet_cell_named`, `_goto_relayed_cell`). The model names the start cell ("D1"); the block path only covered a ref or no target, so real Excel refused `gui type D1 - <<'EOF'` as "one field at a time" (2026-10-19). An A1-style coordinate (refs stay `e12`, lower-case) is now a cell: in a sheet read over AT-SPI it is that cell, made from a listed one; in a host-app viewer the cursor goes there by the viewer's Name Box and Enter, then the block is typed and read back anchored at that cell.
- **Formula syntax is structure, and the person is asked in plain words** (`skills.formulaLiterals`, `functionLedRe`, `cellPlaceRe`, `untracedQuestion`). With the `=` pressed on its own, `IFERROR(VLOOKUP(B2,Prices!$A:$B,2,FALSE),"NOT FOUND")` was refused as data, `Prices!$A:$B` too, and the clerk was asked "Which values should I use? The question a person gets names the values plainly and asks where they come from, never the guard's wording.
- **An app just opened gets a moment before keys are refused** (`core._nothing_in_front(wait=FRONT_WAIT_SECONDS)`). Right after `gui open "Excel (Host)"` no window was in front yet, the next `gui key enter` was refused and the worker spent four actions clicking desktop icons (2026-10-19). The contract also says never to discard an app's recovered files from an earlier session (they may be the person's).
- **A file's facts are checked in code: size, page breaks, the file itself** (`produced.image_findings`, `source_images`, `document_findings`, `missing_requested`, `requested_names`; `office.docx_structure`; `skill_task._gate`). Three reports of success the worker never saw (2026-10-19): a picture "resized to 50%" saved at its old 1200 x 600 (the host copy WAS read and the report said 1200 x 600 - the model check passed it anyway); letters "each on its own page" joined by the characters `\f`; and a request for error_summary.txt answered by a built program, whose report never reached the gate (it returned early: no file written, no screen work). Now, before any model: a picture asked to change size is measured against its source (fetched from the person's computer when the request names its folder) and the size asked; a .docx is read from its XML with page breaks, headings and tables in order, and a missing break or a typed `\f` is not done; a file the request names that is nowhere to be found is not done; a request that names files is always gated; a file on the person's computer that cannot be read is asked about, never passed. The judge's rules say a report whose own evidence contradicts the request is not_done.
- **A desk job is never the coding harness's** (`atomizer.worksAtTheDesk`). "Look through app.log ... (open it in Notepad on your desktop) and write a summary ... saved as error_summary.txt" went to the coding harness, which built and tested a Python package. - **gui type refuses a backslash sequence it has no key for** (`cli._unsupported_escape`). `\f` (and `\r`, `\v`, `\b`, `\a`) outside a Windows path was typed as two characters; it is now refused with how to press the key (a page break is `gui key ctrl+Return` in a word processor).
- **Rows into a host app's sheet start at a named cell, row by row** (`core._type_relayed_rows`, `_name_boxes`). Live in real Excel (2026-10-19): the Name Box was picked as its combobox ("not a field of the app"; the viewer lists a combobox and a textbox, and only the textbox takes a value); and a block typed where the cursor was came out a row off with a circular reference, because a range D1:E26 was selected (Tab and Enter move inside a selection). - **The shell expands $A inside double quotes** (`skills.shellExpands`). `"=VLOOKUP(B2,Prices!$A$2:$C$13,3,FALSE)"` reached Excel as `Prices!:3` (2026-10-19). A gui type with `$` before a letter outside single quotes is sent back to stdin with a quoted end word; a formula read back as `=@...` is the same formula to the grounding check.
- **A long request is planned, not cut off at the job limit** (`long_task.py`, `docs/long-requests.md`). One chat request was one soul job, killed at `THEBOT_JOB_TIMEOUT_SECONDS` (25 min): "I stopped before finishing - ran out of time" on month-end closes and onboarding batches of 45-120 minutes (round 5, 2026-10-19). A request that names several deliverables (`looks_long`, code only, so a short request pays nothing) is planned by one model call into stages run by the workflow runner, each its own job, with a run ledger carried between them.
- **A message sent mid-task waited for the whole task, then ran on its own** (`watchers._pass`, `long_task.take_message`). Leaving ... for later") and then run as a request of its own, after every output already had the bill in it (round 5 spec, 2026-10-19). A message that cannot be read for sure applies nothing and is answered with one confirming question.
- **Artifact paths with a folder were refused on a Windows host** (`workflow_runner.validate`). `Path("close/bank.xlsx")` is `close\bank.xlsx` on Windows, and the check for a backslash refused every workflow output in a subfolder there (found writing the planned-run tests, 2026-10-19). The path is read as the POSIX path it is written as; a backslash the person wrote is still refused.
- **A reply on another task must not carry the running task's tokens** (`messaging.reply_on_task`, `send_query(with_usage=False)`). `send_query` sends the task's running token totals with every reply; a receipt for a mid-run message, sent on that message's own task, would have recorded the whole run's tokens a second time (2026-10-19). - **A borrowed test base must have its cleanups run** (`test_long_requests.WatcherRoutes`). Reusing `test_watcher_restart.Base` by instantiating it and calling `setUp`/`tearDown` left its patches in place - `watchers.threading.Thread` is the `threading` module's own `Thread` - so every later test's threads never started and the full suite hung in `test_model_residency`, whose fake model server never answered (2026-10-19). Call the borrowed instance's `doCleanups`; and import heavy modules before a `patch.dict(sys.modules, ...)`, which drops whatever is first imported inside it.
- **A folder of files goes as one .zip** (`attachments.expand_archives`, `unpack_archive`, `watchers._start_request`; the cap is `httpapi/attachments.go`'s `maxAttachments = 10`, unchanged). The control plane names every attached file in the request's own text, one path a line, and caps one upload at 10 files, 25 MB each and 64 MB together; a month-end close has 19 files (2026-10-19), and the builder of a benchmark round copied inputs onto the worker's own disk to get round it, after which one task answered "I can't find receivables.xlsx on this machine" - it was on the host only. A .zip (by its name, then checked as a zip: an .xlsx is a zip too and is never unpacked) is now unpacked by the agent when it takes the request in - one place for every route that brings files (chat, tickets, email) - into a folder beside it named for it, folders kept, each segment reduced to letters, digits and `_ . -` (what the readers of a request's paths stop at). The request then names the files it holds, one path a line, as if each had been attached. All of it or none: a path that is absolute or leaves the folder, a link, a password, a damaged member, more than 200 files, 100 MB a file or 300 MB in all refuses the archive, removes whatever was written, says why in the chat, and leaves the zip listed as the file it is. The bytes that come out are counted, not the sizes the headers claim. `__MACOSX`, `.DS_Store` and `Thumbs.db` are left out; a zip inside a zip is listed, not opened. Originals are now kept by a file's place inside its upload folder (`attachments._key`), not its base name: the same name in two folders of an archive kept one copy, and the final check could have been shown the other's content as what the person sent.
- **One set of code-decided file checks for every route** (`produced.file_facts`, `FileFacts`; called by `skill_task._gate`, `long_task.code_problems` and `tool_task.perform`). The gate's checks - formula results stored, a Total row of typed numbers where formulas were asked for (else a note), a file the request names that was not made, a picture's size, a document's page breaks - lived inline in `_gate`, so a planned stage's own check, which had copied two of them, never saw the rest (2026-10-19). Now one function returns them and each route reads the fields; a stage passes its own instruction (`named_in`) so it is asked only for the files it names, and its work folder as the root. A fix to a check applies everywhere; add a new fact there.
- **A path is typed as written: precision over recall** (`cli.path_spans`, `_unescape`, `_unsupported_escape`; soul's `pathSpans`, `outsidePaths`). My `\f` check (2026-10-19) refused every typing of `C:\Users\Administrator\Documents\Decurix demo\receivables.xlsx`: the path regex stopped at the first space, so ` demo\receivables.xlsx` fell outside it and `\r` read as a carriage return - the worker could not open its input in Excel's Open dialog (word_letters). Any folder starting with r, f, v, b or a was untypeable. Now a path is a drive, share or `%VAR%` start followed by names that may hold spaces, up to its last folder or file; inside it every backslash is literal (so `\n` and `\t` in `C:\new\temp` are too); a known file extension followed by `\n` or `\t` ends it (a key again). The refusal fires only for an escape standing alone as a token (nothing word-like after it): `\receivables` is a folder, `\fKaveri` is run-on prose that the final check catches in the saved file (`produced.document_findings`). Soul's `typedValues` had the same blind spot for `\n` / `\t` on a Linux desktop (its Windows-path test only runs on Windows); it uses the same rule now. Inside `"..."` bash turns `\\` into one backslash, so a share's path is single-quoted.
- **A block typed through the viewer was killed one row short, and read past** (`core._type_relayed_rows` budget, `RELAYED_BLOCK_SECONDS`, `_table_runs_on`, `shell.go`'s kill message). Live in real Excel (2026-10-19): a 24-row block of formulas is about 2,100 keystrokes, each relayed to the app on its own (about 0.09 s); at the operator's 180 s command limit it was killed on the last row's turn - no read-back, no message, and the model went on to a Total over a table one row short, and reported it verified. The tool did not drop a row; it was killed. Now: a block stops at a row boundary after 110 s (`DECURIX_GUI_BLOCK_SECONDS`), reads back what it typed, ends 4 and says `STOPPED after row N of M ... start again at D{N+1}`; a block of two or more rows whose neighbouring table goes on below it gets a note (not a failure: a header and a first row followed by a fill-down is the advised path); a killed command says it did NOT finish and to look at what it left; the contract and the Excel/Calc guides teach typing a column of one formula once and filling it down (Name Box range, Ctrl+D).
